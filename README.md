# dsh-taskpilot

任务全生命周期追踪。给 DeepSeek Harness 用。

不重做待办清单。DSH 自带的待办能记、能查，就够了。
这个插件只补它没有的三件事：

- **逾期自动追** —— 到点主动催，你不用自己去翻
- **卡住识别** —— 标了「在做」却好几天没动，会被点出来
- **复盘** —— 完成率、准时率、平均几天做完一件、最容易崩的是星期几

## 为什么是这三件

所有「AI 帮你管时间」的工具，卡住的都不是模型聪明不聪明，是**数据进不来**。
日程在别人服务器上，微信里的承诺没接口，邮件里的任务得先解析。
本地待办不一样 —— 它是你自己的文件，读得到。

所以选了这个起点：不跟平台要权限，先把手上已有的数据用透。

## 装

```bash
# 在 profile 目录里
pnpm add dsh-taskpilot
```

或直接从本地目录挂：

```bash
pnpm add file:/path/to/dsh-taskpilot
```

再在 profile 的 `package.json` 里加进 `dsh.profile.bundles`，
然后重载 / 重启 harness。

插件自带 `cordis.patch.yml`，会自动往 loader 插一条记录，不用手写。

## 四个工具

| 工具 | 干什么 |
|---|---|
| `taskpilot_add` | 记一条。标题必填，截止时间写 `2026-11-08` 或 `2026-11-08 18:00` |
| `taskpilot_update` | 改状态 / 截止 / 优先级 / 备注，或者删掉。用 id 或标题模糊匹配 |
| `taskpilot_list` | 看清单。默认只给该关注的：逾期、今天到期、在做，最多 8 条 |
| `taskpilot_review` | 复盘。默认看 14 天 |

状态：`todo` `doing` `blocked` `done` `cancelled`，中文别名也认（待办 / 进行中 / 卡住 / 完成 / 取消）。

### list 的三个档位

| 参数 | 看到什么 | 最多几条 |
|---|---|---|
| 什么都不传 | 逾期、今天到期、在做 | 8 |
| `all: true` | 全部**未结束**任务 | 30 |
| `includeClosed: true` | 未结束 + 已完成 + 已取消 | 30 |

`all` 只放宽条数，不放宽「未结束」这个语义。
调 `all` 却能翻到一年前做完的任务，是两回事 —— 想看历史得明说 `includeClosed`。
要精确看某一种状态，用 `status`，它绕开上面这套默认过滤。

## 后台扫描

默认 15 分钟一次。启动 40 秒后才第一次扫 —— 别和宿主冷启动抢资源。

```yaml
config:
  scanIntervalMinutes: 15   # 扫描间隔，最小 5
  quietHours: [23, 8]       # 这期间不催，支持跨零点
  nagCooldownHours: 24      # 同一件事多久才再催一次
  maxPerScan: 3             # 一次最多催几条，别刷屏
  stallDays: 3              # 「在做」超过几天算卡住
  reviewDays: 14            # 复盘默认天数
  notifyService: ''         # 走哪个 DSH 服务的 send()，例如配了 IM 插件的服务名
  notifyTo: ''              # 推给谁，留空 = 服务默认目标
  webhookUrl: ''            # 或者直接 POST 到这儿，留空 = 只写日志
```

推送有两条路，按需选一条：

**走服务** —— `notifyService` 填一个提供 `send({target, text})` 的 DSH 服务名。
比如装了 QQ / IM 类插件，就填它 `ctx.provide` 的名字，消息直接进聊天窗口。

**走 webhook** —— `webhookUrl` 填地址，POST 一个 JSON：
`{ "text": "...", "msgtype": "text", "content": { "text": "..." } }`。
飞书、钉钉、Slack、自建服务都能吃。

都没配就只写日志，不报错 —— 插件照常追踪，只是不主动找你。

## 四个细节，踩过才知道

**「今天到期」不算逾期。**
纯日期（没有时分）的任务，按当天 23:59:59 算截止。当天就催等于催命。

**复盘按结束时间算成绩，不按创建时间。**
上个月建、昨天才做完的，该算这段时间的成绩。一开始按创建时间筛，结果把做完的漏了 —— 自测里抓到的。

**毫秒值不能靠 `new Date()` 兜底解析。**
`dueMs` 原来直接把字符串丢给 `new Date()`。V8 的兜底解析会把不认识的串当成 1958 年前后的日期，返一个**负数**毫秒值。
负数进来，`isOverdue` 里 `t > 0` 那道判断就静默失效 —— 逾期任务永远催不出来，而且不报错。
现在自己拆 `YYYY-MM-DD [HH:mm]` 的字段、用本地时间构造，再回读校验年月日防 `2026-02-30` 被滚成 3 月。

**`normDue` 和 `dueMs` 的时间口径必须一致。**
`normDue` 早前把 `18:75` 用 `Math.min(23, ...)` 钳成 `18:23`，分钟位完全不校验。
写进去之后 `dueMs` 又解析不出来，返回 0 —— 这条任务的截止时间等于没设，永远不催。
现在 `normDue` 直接拒绝越界的时分，让用户当场看到错误，而不是存一个悄悄失效的值。
测试里有一条用例专门把两个函数的产出对着钉：`normDue` 收下的，`dueMs` 必须认；`normDue` 拒的，`dueMs` 也必须给 0。

## 数据

`~/.dsh/taskpilot/tasks.json`，纯 JSON。
能直接打开看、能自己备份、能扔进 git。没有数据库，坏了就先改名成 `.broken-<时间戳>` 再重开，不覆盖你的旧数据。

**版本与迁移。** 文件顶层有个 `version`，现在写的是 `1`。
读到缺 `version` 的老文件、或 `version` 小于当前值，插件补上版本号后原地写回一次，`tasks` 一个字不动。
读到 `version` **比插件更新**的文件，插件直接报错停手 —— 既不重命名，也不写回。
理由是：新版本的字段旧版本不认识，让它「尽力而为」地写一遍，等于把文件降级覆盖。

## 测试

```bash
node --test "test/**/*.test.js"
# 或
pnpm test
```

零运行时依赖，测试也只用 `node:` 内置模块，离线可跑。
每条用例各自 `mkdtempSync` 出一个临时目录当 `storePath`，不碰 `~/.dsh`，
所以本地跑测试不会污染你真实的待办。webhook 那条用本地 `http` 服务收包，不出网。

92 个用例，分三层：`store`（原子写、版本迁移、坏文件隔离）、`notify`（催办选谁、冷却、静默时段、死键清理）、`index`（四个工具的行为与参数边界）。三层都对着真实文件跑，不 mock 存储。

## 状态

0.2.0。这一版把「看起来能用、其实没生效」的地方清掉了，并第一次带上测试。
下面这些是 0.1.0 之后修的：

- `18:75` 这类非法时刻会被悄悄钳成 `18:23`，存进去后解析失败，任务永远不逾期、永远不催
- 乱码截止时间被 `new Date()` 兜底解析成 1950 年代的负值，逾期判断静默失效
- 催办记录按任务 id 只增不减，任务删了键还留着
- `all=true` 与工具说明相反：说明写「未结束」，实现连已完成一起列
- 库里的 `version` 只写不读，将来没法迁移
